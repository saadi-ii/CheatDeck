PHASE 4 - PLAYGROUND
====================

Goal: let readers edit and run code blocks in the browser.

Approach
--------
Sandpack (CodeSandbox's in-browser bundler). It runs JS, TS and React fully
in the browser with no backend. It is lazy-loaded so normal readers never
download it.

Files to create
---------------
features/playground/
  components/playground.tsx       Sandpack wrapper (client component)
  components/run-button.tsx       "Run" toggle shown on runnable blocks
  lib/templates.ts                map block.language -> Sandpack template
                                  (vanilla, vanilla-ts, react, react-ts)
Update:
  features/cheatsheet/components/code-block.tsx
    if block.runnable, show Run button; on click dynamic-import playground.
  features/editor/components/code-block-editor.tsx
    runnable toggle plus template select.

Rules
-----
- Use next/dynamic with ssr: false so Sandpack loads only on demand.
- Only blocks marked runnable get a Run button.
- No user code ever runs on the server.

Later options (not part of this phase)
--------------------------------------
- WebContainers for real Next.js runtime (needs COOP/COEP headers scoped to
  a playground route, Chromium-first).
- Piston or Judge0 for Python, Java, C++ (needs a small VPS).

Done when
---------
A runnable JS/React code block opens an editable playground and runs, and
the home page bundle size is unchanged.
