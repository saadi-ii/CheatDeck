PHASE 3 - ADMIN EDITOR
======================

Goal: create and edit everything from the browser, with no code changes.
STATUS: done. Verified end to end in a browser against an in-memory mock of
the API (login, create, edit, reorder, rename, publish, delete, logout).

Pages
-----
/admin/login            password form (outside the guarded route group)
/admin                  list: status badge, edit, view, delete
/admin/new              title + slug (auto-generated, validated) -> creates a draft
/admin/[slug]           the editor
Files: app/admin/layout.tsx (QueryProvider), app/admin/(panel)/layout.tsx
(AdminGuard + AdminBar), app/admin/login/page.tsx

How auth works
--------------
- The browser calls /api/* on its own origin; next.config.ts rewrites that to
  Express. The cookie is therefore first-party, which also works in
  production when the frontend and API are on different domains.
- proxy.ts redirects /admin/* to /admin/login when the session cookie is
  missing. This is an optimistic check only.
- AdminGuard calls GET /api/auth/me. A 401 (expired or forged cookie)
  sends you back to the login page. The API is the real authority.
- The public site never sends the cookie, so drafts can't leak into caches.

Editor behavior
---------------
- Edits happen on a local draft. Save sends ONE PUT with the whole document.
- Save is disabled until something changes. Ctrl/Cmd+S also saves.
- The tab warns before closing with unsaved changes.
- Sections and blocks are reordered with up/down buttons (no drag-and-drop).
- Text blocks have Write / Preview tabs (markdown). Code blocks have a
  language select and a "Runnable in playground" checkbox (used in Phase 4).
- Publishing is the "Published" checkbox in the editor, saved with the rest.
- Renaming the slug redirects to the new URL after saving.
- API validation errors are shown in plain words at the top of the editor.
- Reserved slugs (admin, api, new, login) are rejected by both API and UI.

Known limits (by design, kept simple)
-------------------------------------
- Unsaved-changes warning covers closing the tab, not in-app link clicks.
- Public pages can be up to a minute stale after a save (fixed in Phase 5
  with on-demand revalidation).
- No image upload, no version history.
